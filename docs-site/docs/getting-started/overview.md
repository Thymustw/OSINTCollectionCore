# 這是什麼

## 一句話

**OSINT Intelligence Core 是一個情報處理平台的「核心引擎」**：負責把公開情報收進來、
整理、抽出重點、找出關聯，並透過 API 提供給其他應用程式使用。

## 它解決什麼問題

做威脅情報或開源情報分析時，常見的痛點是：

- 資料散在幾十個來源（資安公告、部落格、RSS、情報分享平台），格式各不相同
- 同一則消息被十個網站轉載，看起來像十件事
- 一篇報告裡提到的 IP、漏洞、網域，要人工一個個複製出來
- 兩篇不同來源的報告其實在講同一個攻擊活動，但沒人發現它們共用了同一個 C2 伺服器
- 半年後有人問「這個結論的原始依據在哪」，已經找不到了

這個平台把這些事自動化，而且**每一筆資料都保留完整的來源證據鏈**。

## 它能做什麼

| 能力 | 說明 |
|---|---|
| **多來源收集** | RSS／Atom、靜態網頁、REST API、手動上傳、JSON、CSV、STIX 2.1 |
| **原始證據保存** | 收進來的原始內容**不可修改、不可刪除**，每筆都記錄來源、時間、雜湊值 |
| **正規化與去重** | 整理成統一格式的「文件」；重複轉載的內容自動歸為同一群組 |
| **指標抽取** | 自動抽出 CVE、IPv4／IPv6、網域、網址、Email、雜湊值、社群帳號 |
| **搜尋** | 關鍵字、片語、布林（AND／OR／NOT）、日期範圍、語言、中文；另有語意搜尋 |
| **關聯圖** | 實體之間的關係存進圖資料庫，可以查鄰居、找最短路徑 |
| **實體合併** | 自動判斷兩個實體是不是同一個東西（例如同一個組織的不同寫法） |
| **發現新關聯** | 從一個已知實體出發，找出相關但還沒被納入調查的漏洞、程式庫、產品、情報來源 |
| **AI 輔助** | 用本地部署的大型語言模型協助判斷實體是否相同（可選，AI 掛掉不影響基本功能） |
| **STIX 2.1** | 匯入與匯出，可以跟其他威脅情報平台交換資料 |
| **維運監控** | 每個服務都有健康檢查與 Prometheus 指標，另有維運用的狀態 API |

## 它不做什麼（目前）

請先知道這些，避免期待落差：

- **沒有網頁操作介面。** 所有操作走 API 或命令列。唯一能用眼睛看的是 Neo4j
  內建的圖資料庫網頁。
- **不會從自由文字辨識人名、組織名。** 指標抽取靠規則（CVE、IP 這類有固定格式的東西）。
  人名只從文件的「作者」欄位取得；組織目前只有 STIX 匯入會產生。
- **不會自動去外面抓新資料來擴充調查。** 「發現新關聯」是在**已經收進來的資料裡**找，
  不會主動上網搜尋。
- **還沒有自動化規則與警示**（那是 V0.4 的範圍）。

完整清單見 [目前的限制](../architecture/limitations.md)。

## 技術組成

| 部分 | 用什麼 |
|---|---|
| 核心服務 | Rust（10 個服務） |
| 主資料庫（唯一的真實資料來源） | PostgreSQL |
| 搜尋 | OpenSearch |
| 關聯圖 | Neo4j |
| 原始證據檔案 | SeaweedFS（S3 相容物件儲存） |
| 服務之間的訊息傳遞 | Redpanda（Kafka 相容） |
| 快取 | Redis |
| AI（可選） | 任何 OpenAI 相容的本地模型服務 |

全部用 Docker 容器啟動。細節見 [系統架構](../architecture/overview.md)。
